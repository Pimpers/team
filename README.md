# 🐱 고양이 용병단 — 2D 픽셀 로그라이크 액션

> Unity로 만든 **스테이지 클리어형 로그라이크**. 고양이 용병(검사 / 궁수)을 골라 고대 숲을 돌파하고, 마을에서 영구 강화를 쌓아 더 높은 난이도에 도전합니다.

| | |
|---|---|
| **분류** | 2학년 2학기 게임개발 팀 프로젝트 |
| **기간** | 2026년 2학기 (커밋 180개, 2026-11-01 ~ 11-16 기준) |
| **내 역할** | 팀 프로젝트 내 **코드(게임플레이·시스템) 담당** |
| **엔진 / 언어** | Unity 6 (6000.5.4f1), C#, URP 2D |
| **규모** | C# 스크립트 164개 (약 2만 줄), 씬 17개 |

---

## 한눈에 보기

- **런 구조**: 스테이지 1~5를 진행하고 마지막에 보스(곰)와 싸웁니다. 스테이지 끝의 갈림길에서 경로(A/B)를 고릅니다.
- **빌드**: 스테이지를 클리어할 때마다 카드 3장 중 1장을 고릅니다. 같은 카드를 다시 고르면 레벨업, 같은 태그 카드를 모으면 세트 보너스가 켜집니다.
- **메타 진행**: 런이 끝나면 골드로 마을 대장간에서 영구 강화(공격·속도·체력 등)를 합니다.
- **재도전 난이도**: 챕터를 클리어하면 "타락도" 0~5단계가 열려, 같은 맵을 더 어렵게 다시 돌 수 있습니다.

## 핵심 시스템 (면접에서 설명할 수 있는 부분)

### 1. 카드 · 스킬 시스템 — `CardPool`, `CardDraftUI`, `SkillSystem.*`
- 카드는 `Stat / Active / Passive / Enhance` 4종류, 등급은 `Common / Rare / Epic`으로 나뉘고 등급별 등장 확률 가중치가 있습니다.
- 카드 데이터(등급, 최대 레벨, 쿨다운, 태그)는 코드가 아니라 `Resources/Data/Cards.json`에, 이름·설명은 텍스트 테이블(`Loc`)에 분리했습니다. 밸런스 수정에 코드를 건드리지 않아도 됩니다.
- 스킬 구현은 `SkillSystem`을 `Knight / Archer / Passives / Playstyle`로 **partial class 분할**해 파일 하나가 비대해지는 것을 막았습니다.
- 태그(`Claw, Wind, Fur, Hunt, Treat`)를 서로 다른 카드 2장, 3장 모으면 세트 보너스 1·2단계가 켜집니다. 한 런에 드래프트가 약 4번뿐이라 현실적인 2·3단계로 설계했습니다.

### 2. 타락도(난이도) 시스템 — `Corruption`
- 단계마다 수치(체력 +15%, 이동속도 +6%, 골드 +25%)와 **규칙**(함정 2배, 클리어 회복 절반, 엘리트 분노, 사망 폭발, 보스 2페이즈 시작)을 함께 바꿉니다.
- 처음엔 숫자만 올렸더니 "전투만 길어진다"는 문제가 있어 +30% → +15%로 낮추고 규칙을 추가했습니다. (코드 주석에 변경 이유가 남아 있습니다.)
- `편하게(-1)` 단계를 둬서 진입 장벽도 낮췄습니다.

### 3. 3페이즈 보스 AI — `BossBrain`
- 상태머신(`Move` enum)으로 돌진·바위 던지기·내려찍기·도약 패턴을 관리하고, 직전과 같은 패턴은 연속으로 쓰지 않으며 거리에 따라 패턴을 고릅니다.
- 체력 66% / 33%에서 페이즈가 바뀌고, 짧은 시간에 큰 피해를 받거나 벽에 부딪히면 **그로기**(받는 피해 1.5배)가 되어 플레이어에게 반격 기회를 줍니다.
- 발판 위에서 버티는 플레이(캠핑)를 하면 땅을 쳐서 발판을 흔드는 패턴을 추가했습니다. (플레이테스트에서 궁수가 높은 가지에서 안전하게 공략되는 문제를 발견해 대응)

### 4. 영구 성장 · 저장 — `MetaProgress`, `SaveData`
- 공격(10단계)·속도(5)·체력(3)·리롤(2)·시작 드래프트(1) 업그레이드. 비용은 단계당 +20으로 단순한 곡선을 쓰고, 한 판에 얻는 골드(약 10~20)를 기준으로 맞췄습니다.
- 체력 업그레이드를 5단계에서 3단계로 줄이면서, 이미 구매한 4·5단계는 **환불**하는 마이그레이션을 `SaveData`에 넣었습니다.

### 5. 스테이지 · 월드맵 흐름 — `StageRouteLayout`, `StageExit`, `WorldMapController`
- 월드맵 → 마을/로비 → 스테이지 씬 → 결과 화면으로 이어지는 씬 전환을 `SceneLoader`, `ScreenFader`, `LoadingScreen`이 담당합니다.
- 런 상태(`RunSession`, `RunStats`)는 스테이지 씬이 바뀌어도 유지되고 새 런에서만 초기화됩니다.

### 6. 몬스터 구조 — `Enemy` (partial), `EnemyDefinition`
- 몬스터 종류(슬라임, 쥐, 버섯, 거미, 곰)는 `ScriptableObject`(`EnemyDefinition`)로 데이터화하고, `Enemy`는 `Behaviour / Damage / Status` partial로 역할을 나눴습니다.

## 개발 효율을 위한 도구화

반복되는 에셋·씬 작업은 스크립트로 자동화했습니다.

- **Editor 스크립트**(`Assets/Editor/`): 씬 빌더(`LobbySceneBuilder`, `StageSceneBuilder`), 스프라이트 슬라이스, 오디오·카드 아트 임포트, 전체 런 자동 플레이테스트(`FullRunPlaytest`).
- **PowerShell 도구**(`Tools/`): 이펙트 시트 축소·외곽선·팔레트 통일 등 아트 후처리 스크립트. 각 스크립트는 실행 전 원본을 백업하고 `-Restore`로 되돌릴 수 있습니다.
- **UI 스타일 가이드**(`UI_STYLE.md`): 색 역할, 글자 크기 단계, 레이아웃 규칙을 문서화해 UI 일관성을 유지했습니다.
- 그 외 기능별 문서: [배경 GIF 재생](README_Background.md), [플레이어 애니메이션](README_PlayerAnimation.md), [타이틀 화면](README_TouchToStart.md), [게임 씬 프로토타입](README_GameSceneDemo.md)

## AI 협업 개발

이 프로젝트는 **AI 도구와 협업**해서 개발했습니다.

- Claude Code와 Unity MCP 플러그인(`com.ivanmurzak.unity.mcp`)을 사용했고, 도트 에셋 일부는 Claude 기반 도트 DSL(`pxl`)과 Stable Diffusion 후처리(`sd_cleanup.ps1`)로 만들었습니다.
- 게임 규칙과 밸런스 결정, 플레이테스트 결과에 따른 수정 방향은 제가 판단했고, 구현과 반복 작업에 AI를 활용했습니다.
- 에셋 출처: Kenney UI Pack(CC0, `Assets/Audio/Kenney_License.txt` 참고), Meow Knight 등 외부 스프라이트. 라이선스는 각 폴더를 확인해 주세요.

## 실행 방법

1. Unity Hub에서 **Unity 6000.5.4f1**을 설치합니다.
2. 이 저장소를 clone한 뒤 Unity Hub에서 프로젝트 폴더를 엽니다. 처음 열 때 패키지 복원에 시간이 걸립니다.
3. `Assets/Scenes/TitleScene.unity`를 열고 Play를 누릅니다.

## 이 프로젝트에서 배운 점

- **데이터와 코드 분리**: 카드·몬스터·텍스트를 데이터로 빼니 밸런스 수정이 빨라지고 실수가 줄었습니다.
- **큰 클래스 나누기**: `SkillSystem`, `Enemy`를 partial로 나눠 파일 하나에 책임이 몰리지 않게 했습니다.
- **플레이테스트가 설계를 바꾼다**: 보스 캠핑 대응, 타락도 수치 하향처럼 실제로 돌려 보고 고친 항목이 많았습니다.
- **Git 협업**: 브랜치를 나누고 병합 충돌을 해결하는 협업 경험은 [2025oss](https://github.com/Pimpers/2025oss)에 정리했습니다.
